## 一、做了什么

`app/plugins/sector/frontend.js` 从 651 行的「单表 + 语义榜 + 单板块序列 + 成分股」形态，
换成照 8002 工作台（`夏天-activity/工具/dashboard/web`）重做的板块页。

按主人 2026-10-25 定：

- 层级四档：二级 / 三级 / 概念 / 指数
- 概念层**不再分题材与风格**（当前概念层只有 1 个板块 `999001.TI 物理AI`，分组无意义）
- 比较周期 1 / 3 / 5 / 10 / 20 天 + 日期双滑块 + 前后交易日步进
- 视图只要**表格 / 网格 / 四象**；**折线（`vizCompass`）与热力（`vizHeat`）按主人要求去掉**

## 二、文件结构

拆成五块，避免 8002 那种单文件 189KB：

| 文件 | 职责 | 行数量级 |
|---|---|---|
| `frontend.js` | 状态、取数、编排、工具条、指数层 | ~600 |
| `frontend/compute.js` | 纯函数计算层（榜单/榜位/评分/在榜），零 DOM | ~380 |
| `frontend/board.js` | 表与工具条（两张榜、表头排序、在榜轨迹、浮层） | ~420 |
| `frontend/views.js` | 网格 + 四象 | ~330 |

**为什么这么拆**：计算层与 DOM 分离后可以独立单测（`tests/test_sector_compute.py`，
用 Node 加载真实函数跑断言），渲染层只负责画。8002 里这两层混在 3412 行同一个文件里，
所以它只能靠肉眼看。

## 五、本轮修掉的缺陷（都是自己实测出来的，不是上游报的）

1. **`topCount` 少一层 `⌊n/2⌋` 夹**（compute.js）。8002 有这层，我第一版漏了。
   后果：钻取单个一级行业（19 个板块）时前 10% 拿满 10 个、后 10% 被排空，
   实测 `inN=6 / outN=0`，右栏整个空白。已补，并加守门测试
   `test_top_count_never_overlaps_sides`（n=1..40 全覆盖）。
2. **层级/周期/视图按钮高亮不跟着更新**。切换后数据变了、按钮还停在旧的，
   比不生效更难判断。已加 `_paintControls()` 调用。
3. **状态栏板块数用 catalog 猜**。切层级或钻取时 catalog 与榜单不同源，
   实测「三级 90 个」「钻取电子仍 91 个」。改成按 rankRecent + exclude + 钻取条件现算。
4. **四象图整体失效**。SVG 直接挂进 host，没套 `.sc-quad`，象限线/轴标/气泡样式整批不命中，
   实测「气泡一个查不到」。已补容器。
5. **四象按未挂载容器算宽度**。`clientWidth = 0` 退回 fallback 640，而 SVG `width:100%`
   铺满 1446，被放大 2.3 倍、纵轴溢出。改成先挂容器再测宽。
6. **行内 11 个 span 对表头 10 列**，末列被挤到第二行，整表每行两层。已对齐 11 列。
7. **`.sc-panels` 缺 `min-width:0`**，grid 项被内容撑宽、右栏超出窗口。
8. **四象标签旁注互相遮挡**。改成 8002 的右侧单栅标签列，按 y 堆叠、放不下就停。
