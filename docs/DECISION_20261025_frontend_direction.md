# 前端方向复盘：旧前端 + 新后端（2026-10-25）

## 结论

**方向错了，且错了很久。** 正确路线是「旧前端 + 新后端」，不是「照旧版重写前端」。

## 证据

### 1. 旧前端挂在 8810 后端上，能直接跑

`http://127.0.0.1:8810/legacy/index.html`（旧壳 + 旧页，753KB，10251 行）已在 8810 上可访问。
实测九个 Tab：

| Tab | 耗时 | DOM 节点 | 结果 |
|---|---|---|---|
| 仪表盘 | 7ms | 85 | 通，情绪门/持仓门/选股门三项齐全 |
| 作战表 | 254ms | 410 | 通 |
| 盘中 | 299ms | 4288 | 通，冰点监控 + 恐慌广度 90.6 |
| 板块 | — | 7 | 空——它 iframe 嵌 8002，与 8810 无关 |
| 概念 | 198ms | 1271 | 通，21 活跃 / 15 观察 / 26 链位 |
| 复盘 | 211ms | 733 | 通 |
| 自选池 | 5949ms | 302 | 通，共 28（股 19 / 板块 9） |
| 选股 | 577ms | 806 | 通，表格/卡片双视图都在 |
| 后台 | 171ms | 485 | 通 |

八通一空，唯一的空是板块 Tab 去拉 8002 的 iframe，跟后端无关。

### 2. 接口覆盖率

旧前端共调用 **81 条 `/api/` 路径**，逐条打到 8810：

- 路由存在 **81 / 81 = 100%**
- 其中 2 条（`watchlist/group/remove`、`ui_notes/resolve`）返回 404 是**业务错误**（分组/标注不存在），路由本身在

也就是说，v2 后端（app/core + 19 插件）对旧前端的兼容是完整的。

### 3. 我在做什么

| | 做的事 | 规模 |
|---|---|---|
| 旧前端 | 已有、已调教、已能用 | 10251 行，零改动 |
| 我的重写 | 逐 Tab 重新实现 | 待移植 9974 行（其中共享助手 1969 行、各 Tab 独有 2527 行、其余为重复计数） |

用 9974 行重写去替换一份已经能跑的 10251 行，收益为负。

## 为什么会错

任务书最初写的是「12 张卡逐卡验收 + 主题 token 化 + 补 ops 卡」，那是在**已有 v2 卡片**的基础上收口。
后来主人说「板块照 8002 重做」「盘中照 8002 重做」，我把「重做」理解成「重新实现」，
但主人的意思是「视觉和交互照旧版，不要自己设计」。

真正的分岔点是：v2 卡片前端从一开始就是重写，不是搬运。
证据：旧页 1280 个 CSS 类名，各卡沿用比例——
概念 86%、复盘 90%（这两个是真搬的），
自选池 9%、板块 12%、K 线 0%（这三个是重写）。

## 正确路线

**旧前端当主界面，v2 卡片按需逐个替换。**

1. 8810 首页（`/`）指向旧前端（`/legacy/index.html`），而不是 v2 壳。
2. 每个 Tab 通过 `v2_map.json` 独立开关：想用旧的就 `old`，想用新卡的就 `v2`。
3. 只把「旧版确实不好」的 Tab 换成 v2 卡，其余保持旧前端。
4. v2 卡要替换某 Tab 时，验收标准是**与旧页逐像素对比**，不是「功能齐全」。

这样：
- 立刻可用：旧前端八通一空，今天就能上。
- 无风险：旧前端一个字节不动。
- 渐进：哪张卡做好了换哪张，做不好退回 `old`。

## 待确认

1. 8810 首页是否切到旧前端（当前是 v2 壳）
2. 已重写的 v2 卡（板块、选股、自选池等）是保留待改，还是先全部退回 `old`
3. 板块 Tab：旧前端 iframe 嵌 8002；v2 卡是重写的。要不要保留 v2 卡作为板块 Tab 的实现（它已与 8002 逐格对齐）
