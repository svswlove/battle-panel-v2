# 全局搜索模糊匹配（2026-10-28）

主人要求：作战面板里的搜索加模糊搜索。

## 口径

一次命中即算匹配（多关键词空格分隔时，**每个词都要命中**，命中可以是不同字段）：

| 输入 | 命中方式 |
|---|---|
| `519` / `0519` | 代码**后 N 位**（尾部），纯数字不足 3 位不参与代码检索 |
| `600519.SH` | 全码 |
| `茅台` / `宁德` | 名称任意子串（**至少 2 字**） |
| `mt` / `ndsd` | 拼音首字母（**至少 2 字母**） |
| `guizhoumaotai` | 拼音全拼 |
| `qclbj` / `ldc` | 板块名拼音首字母 |
| `茅台 600` | 多关键词，全命中才返回 |
| `万科` | 名称内部带空格也能搜（「万 科Ａ」→ 归一后为「万科a」） |

排序：完全相等 → 前缀（代码/名称/拼音）→ 其余；同档按名称长度、代码。

归一：名称、关键词、拼音索引统一做 **NFKC（全角→半角）+ 去空白 + 小写**，
所以「万 科Ａ」用「万科」「万 科」「wk」「wanke」都能命中（2026-10-28 主人报的问题）。

代码口径（2026-10-28 主人二次定）：

- 纯数字 **至少 3 位**才参与代码检索，且只比**代码尾部**（`519` → 600519/000519…，`600` → 000600/600600…）；
- 1～2 位数字（`5`、`51`）不查代码，避免一大片噪声；只走名称/拼音；
- 6 位全码（`600519`）即尾部全匹配；带字母/点（`600519.SH`、`sh600519`）仍按全码子串；
- 排序：数字关键词命中的代码后缀排在名称/拼音命中之前。

名称/拼音口径（2026-10-28 主人二次定）：**至少 2 个字符**——单字（`茅`）与单字母（`m`）不搜，
返回空；纯数字 token 不拿去比名称/拼音。

## 实现

- `tools/build_pinyin_index.py`：**构建期**用 pypinyin 生成
  `engine/state/pinyin_index.json`（5945 条，股票名 + 板块名 → `{f: 全拼, i: 首字母}`）。
  运行时**不依赖 pypinyin**（不装进 qmt312 交易环境）。
- `app/core/paths.py`：`READABLE_JSON` 加 `pinyin_index`；`compat/plugin.json` 的
  `data.json` 同步声明，走现有 `ctx.json_read` 白名单。
- `app/plugins/compat/backend.py`：
  - `_pinyin_map(ctx)`：索引读取（缺失/损坏 → 空表，退化为代码+名称，不报错）；
  - `build_search`：代码任意段 + 名称子串 + 拼音全拼/首字母，多关键词全命中；
  - `_search_sectors`：板块名同步加拼音（旧端本来就有，本批补齐）。

## 重建与边界

- 新股上市、改名、板块新增后跑一次：`python tools/build_pinyin_index.py`
  （系统 Python 已装 pypinyin；qmt312 环境未装）。
- 多音字按 pypinyin 默认读音，只作召回，不展示；错读可能导致个别票搜不到，用名称/代码仍可命中。
- 索引是静态文件，服务进程内不热更（重建后需重启 8810 或等下次重启）。
