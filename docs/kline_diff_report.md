# kline 双跑比对报告（旧 8800 vs 新 8810）

**结论：历史日线基本一致；v0.1 是子集，不是完整替代。**

- 生成时间：2026-10-22
- 旧：`http://127.0.0.1:8800/api/kline/{code}?period=d&limit=120`
- 新：`http://127.0.0.1:8810/api/p/kline/bars/{code}?limit=120&adjust=qfq`

## 覆盖结果

对 7 个代表标的比较最近 3 个共同交易日的 `open/high/low/close/volume/amount`：

| 标的 | 共同 bars | 差异 |
|---|---:|---:|
| `000001.SH` | 119 | 0 |
| `000001.SZ` | 119 | 0 |
| `600000.SH` | 119 | 0 |
| `300750.SZ` | 119 | 0 |
| `512480.SH` | 116 | 0 |
| `399006.SZ` | 117 | 0 |
| `399001.SZ` | 117 | 12（最大约 0.03） |

`399001.SZ` 的差异是**源精度**：旧 8800 保留 3 位小数（11820.012），`track_pool.db::kline` 存 2 位（11819.99）；不是前复权公式差异。

## v0.1 未覆盖（与旧端点的真实差距）

- **当日未收盘 bar**：旧端点会从实时源补当日 bar；新版只读 `track_pool.db::kline` 的已完成日线。因此旧端 `bars` 最后一条可能是今天，新端最后一条是昨天。
- **指标列**：`yellow / white / amv / amvMa / amvWhite / chg / amp / turnover` 未迁移。
- **多周期/分时/盘口/板块归属**：未迁移。
- 旧端点 `limit` 实际不截断（固定约 120 根）；新端点支持 `limit` 1–500。

## 当日 bar / 指标列的处置：选定“历史日线子集”

上一版留的二选一（① 补当日 bar、② 卡片降级并标注）已拍定：**取 ②，明确保持历史日线子集**。

- 不引入实时行情源。当日 bar 需要独立实时源，在 kline 插件内做不了，也不该做。
- 不复制 AMV/指标计算。指标归 amv 插件；kline 重算会形成第二个指标口径，违反“一个指标一个 owner”。
- 边界改为**接口显式声明**，不再靠文档口口相传：`/bars` 响应新增 `intraday: false`、`last_bar_date`、`notice`；卡片固定显示“历史日线 · 不含当日/指标”徽标，状态行追加“至 <last_bar_date>”。
- 现有字段全部保持兼容：`code/period/adjust/stale/warnings/bars` 与 bar 内 7 个字段未改。

这是 **v0.1 的有意边界，不是未完成的 bug**。后续要补当日 bar，走独立实时源接入 + 版本升级，不在本版范围。

## 切流建议

- 历史 K 线可 shadow。K 线卡片现在自带“历史日线 · 不含当日/指标”徽标，可直接切；若下游依赖当日 bar 或 yellow/white/AMV 叠加，仍不切，或由调用方读 `intraday=false` / `notice` 自行降级。
