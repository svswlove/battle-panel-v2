# vipdoc 北交所日线缺口核查（只读，结论：不回填）

日期：2026-10-23 ｜ 范围：只读 vipdoc 与 data/*.db，未修改任何数据

## 0. 处置结论（主人 2026-10-23 定）

**不回填。** 理由：

- 历史日线主要用于**回撤/复盘**，与当前在做的面板 v2 开发关系不大；
- 现行取数以 **eltdx** 为主，vipdoc 只在旧 8002 的少数口径里用；
- 没必要把数据库也搬过来：**系统做完再迁数据很简单**，现在就迁等于两边同时维护，成本翻倍。

因此：本报告的实测数据保留，作为「已知缺口 + 补数可行性」的备案；**不安排任何补数动作**。
若将来真要修，按 §5 方案走，且仍须单独授权（写 vipdoc 属破只读边界）。

## 1. 缺口是否只在北交所

口径：先筛「首根 ≤ 20250930 且末根 ≥ 20261022」的可比文件，再算缺口天数——否则退市股、20261021 后上市的新 ETF（n=2）会被误计为缺口。

```
sh sample=20 eligible=13 has_20261008=13
sz sample=20 eligible=7  has_20261008=7
bj     eligible=277 has_20261008=32
   missing_gap_days distribution: [(0, 32), (242, 245)]
```

北交是二值分布：要么整段 242 天全丢（245 个），要么完好（32 个），没有中间态。

若按「最后 80 根是否含 20261022」的粗口径，抽样为沪 16/20、深 15/20（4+5 个不达标者全是退市股或 n=2 新 ETF），不能当缺口证据。

245 个文件中 6 个缺口前最后日为 20250430（2025-05 起长期停牌），复牌日同为 20261009。**复牌日 100% 一致，无个别差异**。

## 3. 三个库的覆盖与回填能力

### track_pool.db::kline —— 可回填

```
distinct BJ codes: 602   date range BJ: 20200727..20261022  rows=473018
920087.BJ: 20221207..20261022, 937 根, 含 20261008
broken 245 → track_pool_full242=237  partial=8  zero=0
partial: 920023(241) 920058(232) 920090(241) 920179(237) 920575(241)
```

字段级校验（920087 / 20261009，两源逐字段相等）：

```
vipdoc raw: (20261009, 1483, 1730, 1475, 1692, 429711552.0, 26410214, 0)
db  vol/amt: 26410214.0  429711552.0      ← OHLC 亦全等
```

即 kline 与 vipdoc 同为不复权原始价、同量级，回填无需换算。

### amv_board.db —— 量能可用，价格不可用

```
stock_state: 2026-09-02..2026-10-22, 31 个交易日, 354 个北交码, 仅命中 21 天(区间尾部)
stock_amv  : 2024-09-25..2026-10-22, 500 天, 354 码, 覆盖缺口 242/242 天，但只有 amv 一列
```

`stock_state` 只有 `alive/sh`，`stock_amv` 只有 `amv`。**缺 OHLC 与成交量，无法重建 .day 记录**；只能用作回填后的成交额交叉校验。

### ths_index.db —— 不可回填

```
920 codes: 0
仅 899050.BJ (北证50): 20250827..20261016, 273 根
meta failed_codes=886109.TI
```

只有北证 50 指数，无 920 个股。

### 旁证：minline 只能覆盖 1/4

`vipdoc/bj/minline` 对 920087 覆盖缺口内 64 天（20260507–20260902），`fzline` 仅 13 天（20260810–20260902）。可作为该段的独立校验源，不能作主源。

## 4. T0002 盘后下载配置

```
download2.dat  0 B
download3.dat 75 B  → 3 条 25 字节记录: 000300 / 000510 / 000905（指数代码）
download4.dat 75 B  → 同上
T0002\log\*.log 3 个文件均 0 B

```

结论：**无可用盘后数据下载清单**。那 3 个代码是沪深指数，不是北交个股；且无下载任务计划、无日志，客户端不可能自动补出中段。

## 5. 推荐方案

**从 `track_pool.kline` 导出 242 天 × 245 码，重写 vipdoc 北交日线；8 个残码先按日对齐再补。**

步骤：
1. 备份 `vipdoc/bj/lday` 整目录（当前版本，勿动已有的 `.bak-20261007`）。
2. 按 `20251009–20261008` 逐码取出 `trade_date/open/high/low/close/vol/amount`，按 `<IIIIIfII` 打包（价 ×100、四舍五入），插入到 `20250930` 与 `20261009` 两根之间。
3. 校验：回读重算——每码根数 +242、日期严格递增、与 track_pool 逐字段比对、`minline` 的 64 天段抽 10 码比对 OHLC。
4. 8 个残码（920023/920058/920090/920179/920575 等）用 minline 补其覆盖段，剩余洞保持缺失并在清单标注，不做插值。
5. 写前先产出到独立目录做 diff，不原地覆盖。

## 6. 风险与不确定项

- **写 vipdoc 属破只读边界**，需单独授权；本次未动。
- 8 个残码在 track_pool 内的缺失日是否停牌，未核（缺 `stock_state` 对应日期的 `alive` 判定，且该表只到 2026-09-02）。
- `.bak-20261007` 只有 366 个文件、691 根，说明缺口早于 20261007 就存在，不是一次写入失败，回滚该备份无效。
- 根因未定：sh/sz 同批完好而 bj 全断，指向 bj 的 `.day` 补写通道独立失效，未做客户端侧复现验证。
