### P1-1 review 卡 CSS「逐字搬入」存在实漂移：旧页 3 条 @media 窄屏规则全部丢失

- **证据**：脚本级规则比对（旧页 `app/web/legacy/index.html` 复盘段 306 条去重规则 vs `app/plugins/review/frontend.js` CSS 数组拼装后逐规则对比）：295 条逐字一致（same），**3 条 @media 规则卡内零对应**——
  - `@media (max-width:760px)` → `#panel-review .rv-md` / `.rv-topline` 的窄屏留白（旧页 1654–1662 行），卡内 `frontend.js` 全文件 **0 处 @media**（`Select-String '@media'` 仅命中注释，CSS 数组为空）；
  - `@media (max-width:900px)` → `.rv-cols-wide { grid-template-columns:1fr }`（旧页 1936 行），卡内 182 行只有宽屏定义。
- **影响**：图表模板三列布局在窄窗口（<900px）不折叠、正文版心不收窄——与旧端观感分叉。HANDOFF「逐字搬入（脚本抽取，不改写选择器）」的自述不成立，属**未声明的口径漂移**（窗口窄时可见）。
- **另**：A 段（49 行起）与 B 段（117 行起）把 v6 正文块整段**重复注入两遍**（`#panel-review .rv-md` 等 33 个选择器 ×2，对比脚本「卡内重复」清单）。功能无害（同值覆盖），但暴露搬运脚本把旧页两处同名段各抽了一次；「逐字」纪律的执行过程不可信，本次漏掉 @media 与此同源。
- **测试缺口**：`test_scoped_css_mirrors_legacy`（test_review_frontend.py:245）只断言作用域不外溢，**没有逐字等值断言**——「逐字」无兜底。
- **建议**：补 3 条 @media；A/B 两段去重；测试加「旧页复盘段规则集合 ⊆ 卡内 CSS」的等值探针。

### P1-2 concept 卡占位芯片点击被详情委托吞掉（可复现实测）

- **证据**：jsdom 真实挂载 `concept/frontend.js` + mock ctx，对活跃卡内 `data-open-kline="000001.SZ"` 芯片派发 `MouseEvent('click',{bubbles:true})`：**卡内详情委托（frontend.js:416 附近 `t.closest('.cp-c[data-slug]')`）先行命中，detail 请求发出、视图切进详情**。旧页同场景由 `index.html:10936` 捕获阶段委托 `stopPropagation()` 保证「芯片可点、卡不误触」；v2 卡在 iframe 里（`v2bridge.js`，R4），父页捕获委托**够不到 iframe 内部**（shell.js / v2bridge.js 中无任何 `data-open-kline`/`postMessage` 委托代码，grep 零命中）。
- **影响**：当前产物形态下（iframe 卡视图），概念卡/链位里的个股芯片、板块芯片点击**既打不开 K 线/AMV，还会误开概念详情**——「占位不误点」的重点验项**不成立**。R3 HANDOFF 只说「桥接后旧页捕获」未说明 iframe 边界；R4 亦无占位转发的交接，属两单之间的交接缝。
